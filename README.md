# HSE Task Tracker 

Сквозной проект по дисциплине "Инфраструктура и администрирование". 

Сервис позволяет вести список задач: создавать, просматривать и отмечать выполненными. 

## Возможности 

- Просмотр списка задач
- Добавление новых задач 
- Отметка задач как выполненных 
- Сохранение данных после перезапуска приложения 
- Проверка доступности и версии приложения 
- Автоматические тесты и проверка проекта в GitHub Actions

## Технологии 

- Python 3.13
- FastAPI
- Uvicorn
- SQLite
- pytest, TestClient
- GitHub Actions

## Установка и запуск

Требуется Знерщт 3.13 и Git
Команды ниже предназначены для macOS и Linux

1. Клонируйте репозиторий и перейдите в папку проекта:
```
git clone https://github.com/Doxylo/hse_task_traker.git
cd hse_task_traker
```
2. Создайте и активируйте виртуальное окружение:
```
python3 -m venv .venv
source .venv/bin/activate
```
3. Установите зависимости:
```
python -m pip install -r requirements.txt
```
4. Выполните из корня проекта с активным виртуальным окружением команду ниже для запуска приложения:
```
python -m uvicorn main:app
```
## Проверка работы 
Приложение доступно по адресу:
- ``` http://127.0.0.1:8000/docs ```

Интерактивная документация:
- ``` http://127.0.0.1:8000/docs ```

После запуска приложения доступны:
- ``` http://127.0.0.1:8000/health ``` - ожидается ```{"status": "ok"}```
- ``` http://127.0.0.1:8000/version ``` - ожидается ``` {"version": "0.1.0"} ```

## Маршруты

|Метод|Путь|Назначение|
|---|---|---|
|GET|/|Приветственное сообщение|
|GET|/health|Проверка доступности приложения|
|GET|/version|Версия приложения|
|GET|/about|Информация о приложении|
|GET|/tasks|Список всех задач|
|POST|/tasks|Создание задачи|
|PATCH|/tasks/{task_id}|Отметка задачи как выполненной|

## Создание задачи

1. Откройте ``` /docs ```
2. Выберите ```POST /tasks```
3. Нажмите ``` Try it out ```
4. Нажмите ``` Execute ```

Требования к данным:
- ```title``` - обязательная строка длиной от 1 до 200 символов
- ```description``` - обязательная строка длиной от 1 до 2000 символов

При успехе сервер возвращает ```код 201``` и созданную задачу
Пример:
```
{
    "id": 1,
    "title": "Отправить ДЗ-1",
    "description": "Файл хранится на рабочем столе", 
    "completed": false
}
```
```id``` назначает SQLite

## Завершение задачи

В ``` /docs ``` выберите ```PATCH /tasks/{task_id}```, введите идентификатор существующей задачи и нажмите ```Execute```

При успехе возвращается код ```200``` и задачу с ```"completed":true```

Если идентификатор отсутсвует возвращается код ```404```:

```
{
    "detail": "Task not found"
}
```

Для проверки ```PATCH``` используйте интерактивную документацию```/docs``` или другой ```HTTP-клиент``` (curl): переход по адресу в строке браузера отправляет ```GET```, а не ```PATCH```

## Проверка работоспособности 

После запуска откройте:

```http://127.0.0.1:8000/health```

Ожидаемый код ответа - ```200```, тело ответа: ```{"status": "ok"}```

Версию можно получить по адресу:

```http://127.0.0.1:8000/version```

Ожидаемый ответ для текущей версии: ```{"version": "0.1.0"}```

Проверка из другого терминала:
```
curl -i http://127.0.0.1:8000/health
curl -i http://127.0.0.1:8000/version
```

## Настройки окружения

|Переменная|Назначение|Значение по умолчанию|
|---|---|---|
|DATABASE_PATH|Путь к файлу SQLite|data/tasks.db|

Относительный путь разрешается относительно папки, в которой находится database.py. Абсолютный путь - без изменений

Пример запуска с другой базой:
```DATABASE_PATH=data/check.db python -m uvicorn main::app```

Если файл отсутсвует, приложение создаст его и подготовит новую пустую таблицу.

В репозитории есть .env.example с примером настройки:
```DATABASE_PATH=data/tasks.db```

## Тестирование

1. Из корня проекта с активным виртуальным окружением установите зависимости для тестирования:
```python -m pip install -r requirements-dev.txt```

2. Запустите тесты:
```python -m pytest -v```

Пять тестов проверяют:
- Ответ /health
- Ответ /version
- Создание задачи и ее появление в списке 
- Ответ 404 при завершении отсутсвующей задачи 
- Завершение существующей задачи и сохранение изменения

Каждый тест получает отдельную временную базу данных.

## Логи и диагностика

Логи выводятся в терминал с запущенным Uvicorn

Uvicorn показывает входящие запросы, HTTP-коды ответов и ошибки обработки. Сервис дополнительно сообщает о подготовке базы при старте, создании и завершении задач

Пример сообщений приложения:
```
Database initialized successfully. Application is starting.
Task created: id=1
Task completed: id=1
```

## Сервис не открывается 

- Проверить, что команда запуска продолжает работать и в терминале появилось сообщение ```Application startup complete```
- Убедиться, что ```http://127.0.0.1:8000``` открывается на том же компьютере, где запущен сервис

## Ошибка No module named ...

- Проверить, что активно виртуально окружение и установлены зависимости 

## Порт уже занят

- Возможно другой экземпляр сервиса уже работает. Остановить предыдущий запуск или использовать другой порт: ```python -m uvicorn main:app --port 8001```

В данном случае адрес сервиса - ```http://127.0.0.1:8001```

## Ответ 404

- Проверить путь запроса. При PATCH убедиться, что задача с указанным ID существует(получить актуальный список ```GET /tasks```)

## Ответ 422

- Запрос не прошел проверку данных. Проверить обязательные поля, длину и типы. 

## Ответ 500 

- Посмотреть traceback в терминале сервера. Последняя строка содержит тип и описание ошибки 

## Список задач пуст

- Проверить значение DATABASE_PATH

## GitHub Actions

```.github/workflows/ci.yml``` запускается при push и pull_request

Выполняются следующие шаги: 
1. Получает код репозитория 
2. Настраивает Python 3.13 
3. Устанавливает зависимости из requirements-dev.txt
4. Запускает python -m pytest -v
5. После успешного выполнения сохраняет artifact task-tracker

artifact task-tracker - архив файлов приложения, тестов и зависимостей 

Результаты доступны в вкладке Actions. Архив нахоится в разделе Artifacts
